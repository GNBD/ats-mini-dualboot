The boot manager gains a **web UI account**: an ID and password kept with the
recovery settings and switched on and off from the Network tab. While it is on
every web endpoint asks for HTTP Basic Auth, so uploads, slot flips and network
changes are protected. Erase stays LCD only and is never exposed over the web.

`Settings > Backup` exports one environment's `settings` NVS region to a
LittleFS file. The name is typed on the same keypad as the WiFi password and
always ends in `.nvs`; Import lists only `.nvs` files, restores one region and
reboots.

`Partition` adds Info, Resize and Repair. Info lists every partition with its
address, size and use, and Repair re-runs the canonical table rebuild. Resize
moves the app0/app1 boundary in 0.5 MB steps (1.0 MB to 6.0 MB per slot) while
both slots are empty, writing the active table and the `0xFFF000` backup; the
per slot `settings` retargeting is left untouched.

`Settings > LittleFS` is a small file manager that lists the volume with used
and free space, and renames or deletes entries with the WiFi keypad.

The web page is reorganised into Status / Firmware / Files / Network / System
tabs with an App slots card that shows each slot's name and version. Upload and
flash now run behind a modal progress dialog that stays up until they finish.
